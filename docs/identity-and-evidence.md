# Identity, evidence and finances

Nine ASCII digits and the Norwegian Mod-11 checksum are mandatory. Spaces/dots and explicit NO/MVA notation are normalised; arbitrary text or embedded digits are rejected. Exact BRREG `organisasjonsnummer` anchors claims. A 404 may try the subunit endpoint, but a subunit's `overordnetEnhet` is labelled as its parent and never used to attach parent finances, roles or group data. A 410 is a legal-removal event and does not use parent/subunit fallback. Registered workplaces must state the requested overordnetEnhet.

Registry-provided sites are candidates, not proof. Current gate: full legal-name text plus exact organisation-number token in collected homepage or same-host contact/legal page, with no other checksum-valid organisation number on that page. Conflicts quarantine the site. This strict rule sacrifices coverage; same-name, parent/group and property-manager sites remain ambiguous. Homepage/contact identity proof is retained in two fact-level evidence spans where appropriate. Child pages stay on the verified hostname and conflicting-number pages are quarantined. Cross-host ownership is not inherited.

Every available claim binds its value hash and organisation number to explicit evidence IDs. Evidence includes requested/final URL, source class/identifier, UTC retrieval, short span or JSON Pointer, content SHA-256, local storage reference, extractor version and known effective/publication time. Unknown publication time stays null; HTTP Last-Modified is stored separately and is never assumed to be publication. Evidence extraction checks that JSON values or text spans actually occur in the snapshot. Additional context pointers support derived financial dimensions, role names/types and subunit addresses. Immutable snapshot bytes can be audited with `scripts/audit_evidence.py`.

CSV snapshots store the original official row and deterministic nested representation; each row records the SHA-256 of its full parent bulk response. Timestamp means actual download completion if acquisition metadata exists; otherwise it is explicitly labelled an evaluator-supplied local snapshot read. A local read is never advertised as live registry refresh.

Financial extraction uses ONLY whitelisted normalised API fields, Decimal parsing and exact organisation_number. Amounts remain decimal strings in the API's reported currency units with scale=1; no multiplication, conversion, revenue inference or model repair occurs. `regnskapstype=SELSKAP` and KONSERN are separate company/group observations. Record ID, journal number, period from/to, exact metric pointer and currency are retained. All returned periods are preserved; missing metrics are unavailable, never zero. Unexpected explicit scales, missing currency/period/scope, or another company number quarantine values. Evidence audit compares the exact amount, period, scope and currency with the stored source record. See verification report for actual checks and scale-source caveat.

Precedence: BRREG owns legal identity; official filed accounts own financial metrics; company websites own only their attributed descriptions/contact/activity. Disagreement across scopes/periods is not a conflict to merge. Concurrent different records remain separate observations; the viewer shows each explicitly rather than silently picking a number. A later failed refresh retains prior facts as stale with their old evidence; stale values cannot count as current coverage.

Revision 2 preserves every legal-name token while normalising case/whitespace/punctuation, and includes literal structured legalName/taxID values in ownership checks. Name similarity or an email-domain match is still insufficient. Contact/legal links are discovered from actual navigation; a sitemap is fetched only when advertised in collected robots and when useful navigation is absent. Cross-host redirects on proof pages must be rejected. Company structured offerings require the exact legal provider; public aliases require the exact legal organization record. Dates have their own supporting spans; historical job postings are not silently called current vacancies.

Financial sample-level semantic review is documented in financial-audit.md. Non-finite/unknown-unit amounts are withheld. Total operating income is explicitly distinguished from sales-only revenue; NUF registration and foreign-enterprise financial scope are labelled. This does not claim that all original filings have been reviewed.

Staff/directory/customer/portfolio pages cannot establish ownership of the publisher's whole site, including when reached as same-host contact proof. A partner's email on an owned site is not the company's own email. Known attribution defects can be retracted with correction evidence while retaining history; blocked refreshes continue to preserve ordinary stale facts. Advice articles remain attributed descriptions rather than inferred named offerings. The validator also rejects summaries referencing stale/unavailable descriptions and retractions that claim an available value.

Business-description claims use company home/about content, not privacy/contact/navigation blurbs. Product excerpts are scoped to the buyable product observation rather than the legal company's general activities. These field-meaning checks are additional to literal evidence binding; a real quote alone does not establish the right category.

## Optional corroborated legal-form policy

`--identity-policy strict` requires full legal-name tokens and exact checksum-valid organisation number. `corroborated` keeps that rule, with a narrowly scoped alternative for AS/ASA/STI legal presentation: literal exact org plus the complete meaningful name core (&/og equivalent), exact registered street and postcode on the same proof page. All four actual excerpts are evidence on the website claim. Foreign enterprises, subunits and other forms do not use this alternative. Every conflicting valid org blocks the candidate, including an earlier contact proof that a later legal page might otherwise supersede. Publisher-profile path guards remain. No address alone, similar name, brand-only match, search snippet or shared group website is sufficient.

Org tokens on collected pages permit bounded Norwegian spaces, dots, hyphens and line breaks, then require checksum validity. CLI inputs retain the original stricter identifier rules. Provenance binding proves that excerpts exist; manual semantic review separately assesses whether they support ownership and extracted facts.
