# Refresh and history

Use a new run ID for each actual refresh. Cached validators produce If-None-Match / If-Modified-Since requests when available. A 304 is a real counted network revalidation; bytes remain content-addressed and a new checked timestamp is recorded. Without validators the full source is requested again. There is no stale response fallback disguised as a successful HTTP check.

Stable claim IDs describe a field (plus financial record/scope/period, person/role or subunit identifier where needed). SQLite's `(org, claim_id, value_hash)` key prevents duplicate observations. first_seen is distinct from last_checked. Retrieval is distinct from effective date, source publication and reporting period. Semantically unchanged values produce no change event even if JSON ordering/retrieval time changes. Old snapshots and observation versions remain inspectable.

Added and changed values carry before/after evidence. A removed registered role/workplace requires a successfully rechecked complete official collection; pagination-truncated collections cannot prove absence. Missing values from bounded website/news/job crawling do not prove deletion and remain last-known stale observations. A blocked/failed refresh does not erase prior facts or update their last_checked; it marks them stale and reports the failed module. A later successful recheck makes them current again. BRREG 410 legal removals are the explicit source-rights retention exception.

Declared scheduling guidance: registry 24h, accounts 30d, company sites 24h, jobs 6h. The submitted runner conservatively rechecks requested sources on every NEW run rather than trusting TTL alone. Re-reading an unchanged evaluator bulk snapshot is labelled as such; it does not establish live freshness. A caller needing current registry changes must omit --bulk or provide a newly dated snapshot.

SQLite checkpoints are keyed by run ID, input byte checksum and organisation number. --resume reuses finished checkpoints only for the same configuration. Durable request reservations and original wall-clock deadline survive interruption, including time while stopped. It cannot reset budgets or silently turn an old completed run into a live refresh. An interrupted identity phase may be fetched again if no finished company checkpoint exists; content/observation keys still prevent duplicate facts. A separate new run is required after the deadline to collect additional evidence.
