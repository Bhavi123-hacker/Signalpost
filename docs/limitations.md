# Known practical limits

This entry is a deterministic no-model baseline. Real verified coverage is measured in the verification report, separately from terminal envelope counts. Registry identities are not automatically externally researched profiles. No official score, recall against the private checked pool, exact-company precision rate for the entire corpus, or qualification is claimed.

Website identity requires exact organisation numbers, static HTML only; the optional corroborated legal-form policy additionally requires exact registered street/postcode and preserves literal proof. Search beyond registry URLs uses actual business-email domains, not guessed domains or a general web index. The documented Wikidata exact-ID feasibility experiment returned no matches on development200 and is not enabled by default. Unregistered domains, property-manager/accountant sites, parent brands, case/name variants, JavaScript pages and blocks reduce discovery. There is no licensed social/search/news feed or browser/OCR fallback. Hiring/news require dated structured company-owned records and remain incomplete when not found in bounded pages; explicit structured alternate names may support public-brand facts; independently verified social-profile collection remains unimplemented and says not checked.

Annual-account history is limited to records returned by the free normalised endpoint; no paid annual-report copy, new PDF parser or regulatory feed is used. The API is the source of reported currency units; we preserve raw decimal amounts with no scaling. Financial scale metadata is not explicit in its current OpenAPI schema. A revision-2 visual semantic review corroborated 31 observations in 10 original filings, including NOK/SEK/USD, negatives and company/group scope; this is a sample, not corpus-wide independent verification (financial-audit.md). Unexpected explicit scales are quarantined rather than converted. No site or model is allowed to repair financial numbers. Workplace crawling is limited to the first 100 records and flags incomplete pagination.

Optional frozen registry snapshots improve the request budget but establish freshness only as of their stated download/cutoff. Source cutoffs are not guessed. The current adapter does not implement historical source reconstruction for an arbitrary retrospective cutoff; the official evaluator must supply its frozen registry and allowed live-evidence window. Time and request defaults are provisional because the retrieved contract supplies no numeric caps. CLI configuration should follow the organiser's actual run settings.

The starter contains only a minimal structural validator, not the organiser's private schema/scoring harness. Its two output examples use different vocabularies; our superset passed local starter checks as reported. Credentials are not needed. No competition submission, email or spending occurs automatically. The GitHub repository was made public after the author's explicit later request; restricted/private evidence remains excluded.

The outer report resource_cutoff flag tracks the outer wall deadline, not all per-module request/allocation exhaustion. Inspect module errors and populated-field counts. Request reservations and the original wall deadline are durable on resume; byte, cache-hit, latency and source-failure counters are invocation-level. All final measured verification runs were uninterrupted, so their counters describe the whole run.

The available 07:00 IST delivery checkpoint was exceeded; final checks/package timestamps record actual later delivery. No timing or qualification claim is inferred. Broad external coverage remains low: bounded request allocation and a missing permitted anonymous search index are the main constraints. A sealed ID-disjoint sample is not necessarily disjoint by website host. Prior installer-contact, advisory-title and privacy-description mistakes were disclosed and generically regression-tested; neither source binding nor a small audit proves corpus-wide semantic precision. Company-site claims/raw HTML are withheld from the distributable export where reuse rights are unestablished; their measured counts remain in unmodified reports, and full source state stays local.

Sealed validation revealed a conservative offering false-negative: two genuine West Mekan B2B product pages are published by the recovery control but withheld by the selected buy-control-or-exact-provider rule. The final version does not claim improved offering coverage and was not tuned after this untouched sample. Selected phone coverage increases there, while substantive company breadth stays5/100. This documented precision/recall tradeoff can be revisited in a future development cohort, not by reusing the sealed sample as a new holdout.

Website refresh is incomplete: the selected second6-company run discovers10 additional contacts on a newly visited page and leaves5 prior contact observations stale, despite rechecking related sources. Values are not silently erased or relabelled fresh; stable first_seen is retained. The source-aware bounded extractor can skip revalidating known text contacts. A separate registry/financial-only control demonstrates idempotency for those modules; it is not evidence of full website freshness.
